# Testing And Verification

## Test strategy

- 핵심 프로토콜 로직(명령 파싱, 상태 전이, 응답 형식)을 테스트한다. 작성 순서(테스트 먼저)는 강제하지 않는다. 단순 설정, 배선, 로깅은 의무가 아니다.
- 전역 규칙(TDD 필수, 커버리지 80%)은 이 프로젝트에 적용하지 않고 커버리지 게이트도 두지 않는다.
- 도구: JUnit 5, Mockito.
- DB를 쓰는 테스트는 작성하지 않는다(CI, 로컬 모두). 테스트는 DB 없이 실행되어야 한다.
- DB 접근, SQL, Flyway 마이그레이션은 로컬 PG에서 서버를 실제로 기동해 확인한다.
- 실제 소켓 동작은 서버를 띄우고 클라이언트(또는 `nc`, `telnet`)로 접속해 수동으로 확인한다.
- 시간이 결과에 영향을 주면 고정된 `Clock`을 주입한다.

## Commands

- 전체: `./gradlew build` (또는 `make build`)
- 일부: `./gradlew :server:test --tests '*ClassName'`
- PR 전에 변경 범위에 해당하는 명령을 통과시킨다.

## Evidence

- 완료 보고에는 실행한 명령과 실제 결과를 함께 적는다. 실행하지 못한 검증(로컬 DB 실기동, 실제 소켓 접속, 원격 배포)은 못 했다고 명시한다.

## Failure handling

- 테스트가 실패하면 구현을 고친다. 테스트가 틀린 경우에만 테스트를 바꾼다.
- Mockito로 확인할 수 없는 동작(동시성, 타임아웃, 실제 네트워크)은 수동 확인으로 보완하고, 미검증이면 보고에 적는다.
